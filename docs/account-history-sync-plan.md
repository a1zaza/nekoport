## 1. 目标与范围

本次增加三项能力：

1. 参照 v2way，在“设置与同步 → 账户安全”修改本平台登录用户名和密码。
2. 对选定邮箱账号同步服务器当前可见的全部历史邮件，突破最近 N 天限制，支持进度、取消和断点恢复。
3. 服务端定时获取新邮件并对齐服务器上的文件夹、标记和邮件删除状态，不依赖浏览器打开。

“平台登录账户”与“邮箱连接账号”明确区分：修改平台密码不修改 IMAP/SMTP 密码，不重新加密或替换主密钥。邮箱服务商密码仍在“编辑连接”中维护。

全历史同步的含义：将该账号所有可选择文件夹中、服务器当前仍保留的邮件元数据完整纳入本地索引，包括主题、地址、日期、已读、星标及附件结构。正文和附件沿用按需读取与缓存预算。这意味着可以搜索和浏览全部历史列表，但不等于完整离线备份，不承诺未读取正文的全文搜索或断网阅读。界面明确说明“同步全部历史邮件列表，正文及附件查看时加载”。

不恢复服务器已经删除或不可访问的邮件；不预置邮件商，不增加服务商专有 API。本期不增加全量正文/附件离线下载、Cron 表达式、远程托管或桌面端。

## 3. 账户安全设计

### 3.1 界面与校验

在设置页增加“账户安全”独立卡片，保持现有中文、深色、紧凑表单样式。

- 用户名预填当前登录名，首尾空格去除，1–64 UTF-8 字节，拒绝控制字符。不更改大小写规则，不将邮箱地址当作登录名自动填入。
- 默认关闭“修改密码”，关闭时不传新密码；打开后显示新密码和确认新密码，切换关闭清空这两个字段。
- 修改用户名或密码都必须填写当前密码；无有效改动不能提交。
- 新密码至少 8 个 Unicode 字符、最多 72 UTF-8 字节，前后端同规则；禁止与当前密码相同，不自动 trim 密码。
- 长度上限匹配本项目现有 bcrypt，不能直接照搬 v2way 的 1024 字节上限；保持现有 bcrypt 摘要兼容，不进行算法迁移。
- 提交按钮为“保存并重新登录”；失败保留输入，成功清空敏感字段并回到登录页，提示账户已更新。
- 成功使所有会话退出。存在未保存写信内容时，先提示保存草稿；保存失败则阻止发起账户修改，避免主动退出丢失编辑。

不增加明文密码查询、默认密码、邮件找回或自动重置。开发凭据记录可能因用户改密过期，不自动覆写私有明文凭据文件；登录以持久化摘要为准。

### 3.2 接口与原子性

新增 `PUT /api/v1/auth/account`：请求包含 `username`、`currentPassword`、可选 `newPassword`、`expectedRevision`。确认密码仅作前端校验，不要求服务端接收重复秘密。

成功返回 200 `{ reauthenticate: true }`，清除当前 Cookie；当前密码错误返回 403，参数无效 422，账户修订冲突 409，限速 429，持久化不可写 503。错误响应沿用本项目 message 格式，禁止回显密码、摘要或请求体。

处理顺序：

1. 现有会话、精确 Origin、CSRF 校验；请求体限制 8 KiB，并限制当前密码输入长度。
2. 账户更新/登录共享认证并发屏障；独立限速，按来源与账户组合控制，默认 5 分钟最多 5 次验证失败。
3. 读取认证快照，校验当前密码和 expectedRevision，验证用户名与密码规则，生成新 bcrypt 摘要。
4. 在 Store.Update 中再次检查账户修订，仅更新 Username、PasswordHash、AuthRevision，保留当时最新阅读偏好；提交到现有 JSONL 事务日志后才生效。
5. 持久化成功后使旧修订会话失效、清空会话表、关闭相关 SSE 连接并清除 Cookie。写入失败则旧凭据和旧会话保持有效，界面提示失败。

慢密码计算不持有 Store 全局写锁。认证屏障/修订检查确保：与改密并发的旧密码登录不能在会话清空后创建一个仍有效的旧凭据会话；并发两次改密只有基于当前修订的一次成功。

### 3.3 会话与字段隔离

- Settings 增加 `AuthRevision`，旧数据缺失按 1 规范化；session 增加对应修订。
- 每次鉴权比较修订；SSE 在认证变更时主动断开，不能只在建立连接时检查。
- bootstrap 仅增加登录用户名与认证修订的公开摘要，不返回摘要密码；普通 settings DTO 继续只接收阅读偏好，拒绝认证字段。
- 已在执行的普通请求不追溯撤销；变更提交后的新鉴权拒绝旧修订。
- 不引入新默认账号，不改动 init 的显式初始化与拒绝覆盖原则。

## 4. 邮件同步产品行为

### 4.1 账号卡片

每个邮箱账号增加：

- “同步范围”：最近 N 天 / 全部历史。默认保留原账号已有范围。
- “同步全部历史”：显式启动历史任务，同时把该账号范围切换为全部历史；说明覆盖该账号所有文件夹，可能耗时，不自动下载全部附件。
- “立即对齐”：按该账号当前范围执行一次完整服务器对账。
- “定时对齐”：开关、间隔、上次完整成功时间、下次计划时间。
- 任务详情：状态、当前文件夹、文件夹完成数、已处理邮件数、阶段、可用时显示预计总数、错误及“继续/重试”“取消”。

全部历史包括收件箱、已发送、服务器草稿、归档、垃圾箱、垃圾邮件及自建文件夹；只排除 IMAP 标记为不可选择的目录。服务器草稿作为远端邮件展示，不混入本地写信草稿列表。

“最近 N 天”只限制新补录邮件范围。已经导入的旧邮件仍保留索引并参与对账，切换回最近 N 天不能悄悄删除既有历史。

账号暂停优先于手动和定时任务；手动点击提示先恢复账号。单独关闭定时对齐不会阻止手动同步，也不会停止用户已明确发起的历史任务。

### 4.2 两类定时工作

| 工作 | 默认 | 行为 |
| --- | --- | --- |
| 快速同步 | 保持每 60 秒；高级设置可调 30–3600 秒 | 获取新 UID、执行已确认的本地邮件操作；不每分钟重新抓取全部历史信封 |
| 完整对齐 | 每账号默认开启，每 15 分钟；范围 1–1440 分钟 | 完整枚举目录和 UID，补漏历史、更新标记、确认远端删除 |

历史任务是同一同步系统的可恢复长任务，不能与完整对齐各维护一套互相竞争的索引写入逻辑。

完整对齐只读取服务器状态，本身不发送邮件、不移动或删除远程邮件。发信与用户操作队列继续按已有语义处理；状态不确定的 SMTP/归档任务绝不因定时器或重启而自动重放。

## 5. 同步算法与一致性

### 5.1 身份与目录发现

- 邮件远端身份沿用 `(accountID, mailboxID, UIDVALIDITY, UID)`，不能用 Message-ID 去重；同一邮件存在多个文件夹时保留多个远端实例。
- 先完整 LIST，跳过 NoSelect，逐个只读 SELECT。文件夹改名无法可靠识别时按新目录导入和旧目录确认消失处理，不猜测服务器 ID。
- 检测 UIDVALIDITY 变化时创建新代次，旧 UID 游标失效，重新枚举该目录。旧代次不参与新 UID 映射；在新代次成功提交后淘汰旧记录，并将对应待执行操作标记冲突，避免对复用 UID 执行误操作。

### 5.2 分段导入与游标

1. SELECT 后记录 UIDVALIDITY 和本轮上界 `UIDNEXT - 1`。UIDNEXT 不可用时先通过有界命令取得实际最高 UID；空目录单独处理，避免将 0 当作 IMAP 的最大 UID 通配值。
2. 按 UID 数值窗口 SEARCH，例如每段跨度 10,000，命令只覆盖当前 UID 区间及本轮上界。窗口内 UID 最多 10,000，避免一次 SEARCH ALL 长期占据无界内存。UID 稀疏时也不假设连续。
3. 所得 UID 每 100 封批量 FETCH。新邮件读取信封、日期、大小、标记和附件结构；已有邮件一般只更新标记，保留本地正文缓存与稳定 ID。
4. 最近 N 天账号对新补录应用日期范围，但仍枚举、核对已导入历史；全部历史不使用 SINCE 截断。
5. 每个批次将邮件变更与任务游标写入同一 Store 事务。游标不得超前于已持久化数据；重试同一批次通过远端身份幂等更新。
6. 断线恢复从已提交窗口重新查询，不能盲信过期 UID 列表；恢复前重新验证账号配置修订与 UIDVALIDITY。
7. 本轮之后新增的 UID 交给下一轮快速同步/对齐，不让持续来信阻止本轮完成。阶段总数允许更新，不显示虚假的精确百分比。

每处理一个批次可释放账号执行权：优先响应取消/暂停及交互读信，给已确认的邮件操作、新信同步留出机会；然后继续历史任务。全局最多两个后台账号执行，同一账号一次只允许一个同步写入阶段，复用现有并发预算，禁止历史任务额外占满连接。

### 5.3 删除与标记对齐

- 以服务器为读取同步的来源：服务器已读/星标变化覆盖本地；有用户操作待提交时，沿用乐观状态，操作成功后再对账。
- 使用同步代次标记本轮见过的 UID。只有目录 SEARCH 全窗口成功、必要 FETCH 成功且配置修订/UIDVALIDITY 未变化，才进入删除确认阶段。
- 失踪 UID 在删除前分批再次 SEARCH 精确确认，避免用早于本地新操作的快照直接删除；账号工作阶段串行，保留本轮上界以外的新记录。
- 命令超时、部分窗口失败、取消、认证错误或连接中断不授权删除。文件夹消失也必须基于成功完整 LIST 并再次确认，NoSelect/访问错误不冒充目录已删除。
- 仅移除已确认失踪的本地远端记录和索引，不执行远程 EXPUNGE；关联本地待操作转为明确冲突，不误报成功。孤立缓存按现有垃圾回收规则清理，不删除本地草稿/发送快照。
- 对账过程中服务器仍可能继续变化，本方案是周期性最终一致，不声称跨文件夹原子快照。下一轮修正枚举期间的移动和标记变化。

### 5.4 失败与恢复

- 任务状态：queued、running、paused、succeeded、partial_failed、failed、cancelled；每个目录有独立阶段和游标。
- 某个目录失败可以继续其他目录，但该目录禁止删除扫尾，账号不更新“完整对齐成功”；重试只恢复未完成或失败目录。
- 网络/临时服务错误使用 1、2、5、15 分钟退避，最大 1 小时，并加入少量抖动；成功后清零。
- 确定认证失败暂停自动重试，界面明确提示；更新连接凭据或手动重试后允许恢复。TLS/协议配置错误区分提示，不冒充密码错误。
- 取消只停止后续批次，已提交邮件保留；界面提供继续任务。账号配置变更使旧游标需要重校验；账号删除时终止任务后再清理账号数据。
- 重启将运行中读取任务恢复为 queued 并校验游标；这项恢复只适用于幂等读取同步，不能套用到 SMTP 或远端写操作。
- 进度写入失败遵循现有冻结规则，停止同步状态写入，保留日志恢复边界，不忽略损坏继续处理。

## 6. 调度与数据模型

### 6.1 内置调度器

一个 Go 调度循环管理到期任务，不为每个账号创建独立永久 ticker。持久化任务意图、运行结果和恢复游标，运行中的 context/连接/计时器只保存在内存。

- 同账号任务合并去重：一次历史任务进行时，不再堆积周期对齐；记录至多一次后续对齐意图。完整对齐不能被快速同步覆盖降级。
- 快速同步可在历史任务批次之间运行；用户手动任务优先于下一次周期任务。
- 每次执行结束更新下一次时间，间隔从结束计算；耗时大于周期不创建无限积压。
- 容器停机期间不运行任务。启动后到期任务只补一次，按账号错峰，不补跑每一个错过的周期。
- 时间持久化使用 UTC；运行间隔使用 Go 的单调时间能力，墙钟跳变后重新计算到期状态，不忙循环。
- 关闭调度/暂停账号后立即取消计时中的待触发项；运行阶段在批次边界退出并保存游标。

### 6.2 字段划分

| 对象 | 建议新增字段 | 用途 |
| --- | --- | --- |
| Settings | authRevision、quickSyncIntervalSeconds | 认证变更及全局快速轮询 |
| Account | syncScope、reconcileEnabled、reconcileIntervalMinutes | 当前补录范围与周期配置 |
| MailboxSyncState | accountID、mailboxID、uidValidity、lastObservedUID、lastReconciledAt、generation | 按目录区分新信水位与完整成功状态 |
| SyncTask | id、accountID、kind、trigger、state、accountRevision、createdAt/startedAt/finishedAt | 持久化任务身份与生命周期 |
| TaskMailboxProgress | taskID、mailboxID、uidValidity、phase、upperUID、committedWindow、processedCount、error | 分目录恢复与进度 |
| AccountSyncStatus | lastQuickSuccessAt、lastFullSuccessAt、nextDueAt、retryAt、errorKind、pendingReconcile | 调度与界面状态，避免混用账号配置修订 |
| Message | lastSeenGeneration | 分段完成后的缺失记录判断 |

这些是逻辑对象，可作为现有 State 的新增映射及 JSONL 操作类型，不新增数据库，也不另写一套无事务的任务状态文件。公开 API 使用独立 DTO，不直接返回密码摘要、凭据引用或内部 UID 快照。

“lastObservedUID”不能替代完整导入游标：高 UID 新信可先被快速同步发现，但低 UID 历史仍可能尚未导入；“最后成功完整对齐”也不能在仅完成部分目录时更新。

历史任务完成后压缩目录游标，只保留摘要；每账号保留最近 20 次终态任务，进行中/暂停任务不被清理。数据批次限制 100 封，SSE 进度最多每秒推送一次，避免日志和前端刷新风暴。

### 6.3 旧数据兼容与容量

- 缺少 syncScope 的账号映射为 recent，沿用原 syncDays；选择 all 后保留原天数以便切回。
- 缺少周期配置的账号默认 15 分钟完整对齐，快速同步继续 60 秒；paused 账号保持暂停。
- lastSync 保留兼容显示，新增独立完整对齐时间，不把旧 lastSync 当作历史导入已完成。
- 老 checkpoint/JSONL 能规范化新增空映射与字段，启动恢复后补任务；不重写真实邮箱凭据。
- 全量元数据不计入正文缓存预算，也不随正文缓存 LRU 被删除，但会增长 JSON 文件和内存索引。界面显示邮件数、元数据占用与缓存占用的区别。
- 现有 Store 更新的索引重建/状态复制成本必须在实施前针对 1 万/10 万邮件测量；批次提交不得因每封邮件全量扫描状态而退化为明显平方成本。同步查询使用账号/目录/远端身份索引，不对全部账号反复扫描。
- 大目录不能静默截断；出现内存或存储不足时暂停并显示已完成范围，不能宣称已同步全部历史。分段同步降低临时开销，不承诺常驻完整索引为常量内存。

## 7. API 设计

| 方法与路径 | 作用 |
| --- | --- |
| PUT `/api/v1/auth/account` | 修改本平台登录用户名/密码，成功要求重新登录 |
| PUT `/api/v1/accounts/{id}/sync-settings` | 更新 scope、recentDays、reconcileEnabled、intervalMinutes，带配置修订 |
| POST `/api/v1/accounts/{id}/sync-tasks` | 创建 history / reconcile / quick 任务，返回 202 与任务 ID |
| GET `/api/v1/accounts/{id}/sync-tasks` | 分页查看该账号任务摘要 |
| GET `/api/v1/sync-tasks/{id}` | 获取任务阶段与分目录进度 |
| POST `/api/v1/sync-tasks/{id}/cancel` | 幂等取消，保留已完成数据 |
| POST `/api/v1/sync-tasks/{id}/resume` | 继续暂停/取消/失败任务，经配置和 UIDVALIDITY 校验 |

创建 history 任务与把 scope 切换为 all 在同一事务中提交。重复点击或断线重试复用客户端 requestKey，服务端按账号与活动任务去重。已完成任务不能重新打开游标，用户再次点击创建新的校验任务。

现有 `POST /accounts/{id}/sync` 保持兼容，映射为普通 quick 触发并进入同一队列；返回实际任务摘要，前端逐步迁移。bootstrap 增加账户安全公开摘要与每账号同步状态，详细目录进度仅按需获取，避免每秒发送全部历史数据。

所有写接口继续精确 Origin、会话和 CSRF 校验；修改账号参数错误、任务冲突和存储冻结必须区分。读取进度、任务取消和恢复都受登录保护。

## 8. 界面交互补充

设置页按“我的邮箱 → 同步与任务 → 账户安全 → 阅读偏好”组织，账号卡片提供范围和任务入口；详细进度使用现有弹窗/展开面板，不引入新导航系统。

- 尚未启用全部历史：显示“最近 N 天”，提供“同步全部历史”。
- 历史进行中：显示“已导入 12,340 封 · 正在处理 已发送”，可取消；不以已处理/未知总数伪造百分比。
- 部分失败：列出失败文件夹，显示其他目录已完成，不误报全部完成。
- 完成：显示“全部历史列表已同步”，正文缓存仍独立显示。
- 周期状态：显示下次计划；认证阻塞、账号暂停、定时关闭分别展示，不能统一成“正常”。
- 通过 SSE 通知状态变化，前端断线后主动拉取任务快照，不依赖每条事件都送达；普通点击不等待长任务 HTTP 请求结束。

## 9. 实施顺序与验收

本次按以下顺序完成实施：

1. 登录账户修订、认证变更接口和会话失效；增加账户安全表单。
2. 先拆分读取同步与发送/操作执行边界，建立持久化任务、目录游标和去重机制。
3. 全历史分段导入、目录/UIDVALIDITY 处理、取消恢复和完整删除确认。
4. 内置定时调度、退避和状态展示；替换现有只展示“后台每分钟轮询”的固定文案。
5. 旧数据兼容、容量测量及端到端回归。

### 必须通过的验收

- 仅改用户名、仅改密码、同时修改、错误当前密码、新旧密码相同、多字节长度边界、无变化、关闭密码开关不提交秘密。
- 存储写失败不变更凭据/不撤销会话；并发登录/改密和并发偏好保存无越权或覆盖；旧 Cookie、其他标签页及 SSE 按预期失效。
- 使用本地模拟 IMAP，覆盖超过 3650 天的邮件、全部目录、稀疏 UID、大批量分页、已有缓存稳定 ID、重复触发及分段提交失败。
- 窗口间断线/进程重启恢复不漏信不重复；UIDVALIDITY 变化不对新邮件误执行旧操作；配置修改与暂停可终止任务。
- 远端已读/星标变化、删除和目录消失能对齐；部分失败、取消、陈旧快照不得批量误删。并发新增/移动能在下一轮收敛。
- 可控时钟验证默认周期、关闭定时、错过周期只补一次、执行超时不积压、退避与手动恢复、同账号互斥及跨账号并发上限。
- 1 万/10 万邮件记录内存、一次批次延迟、初次导入与完整对账耗时；发现 Store 索引重建瓶颈后再调整，不以小数据测试替代。
- 浏览器模拟接口验证桌面/手机及局域网 HTTP 的账户安全、进度、取消/恢复和写信回归。不使用真实邮箱执行删除/改密测试，不发送真实邮件。

本方案已获后续实施授权。实现和验证不修改用户真实登录密码，不手动触发真实邮箱历史任务；没有执行 Docker 构建、Git 操作或远程发布。


## 10. 实现记录与验证

- 账户修改接口与前端卡片已完成。认证修订与 bcrypt 摘要进入同一个现有日志事务；认证并发屏障避免旧密码并发登录越过撤销边界，SSE 使用认证变更通道立即关闭。
- 同步任务、每目录游标与账号调度状态均进入 JSON/JSONL；原同步算法已移除，原有协议测试也改用新任务引擎。
- 单个账号只运行一个执行阶段。为避免历史导入阻塞新来信，允许同时保留一个主任务与一个辅助快速任务记录，串行优先处理快速任务，定时触发不积压。
- 每批最多 FETCH 100 封，一个账号执行片最多处理 8 个步骤后释放全局工作槽；后台账号并发为 2。默认快速同步 60 秒、完整对齐 15 分钟，可由设置调整。
- UIDNEXT 缺失时仅 FETCH 最后一条序号的 UID 取得上界；枚举发生竞争时重试，不能误判为空目录。缺失候选 UID 逐批二次精确查询，包括服务器最高 UID 消失的情况；仍存在的新邮件会保留。
- UIDVALIDITY 改变时先分批失效旧映射并将待执行操作标为冲突，再导入新代次。NoSelect 目录不参与导入，但保留在目录存在性确认中，避免误判删除。
- 部分目录失败后可继续其他目录；继续任务时重新 LIST，并保留已完成目录进度，确认消失的目录才能清理本地记录。改变同步范围为近期时暂停旧历史任务，继续历史任务会明确恢复全部历史范围。
- 运行中账号仍使用原有移除保护：先取消同步并等待账号工作结束，再移除，避免中断正在发送的 SMTP 事务。同步任务取消不回滚已导入邮件。
- SSE 更新合并为最多每秒一次并保留最后一次通知；任务界面每 5 秒在可见页面校验快照。任务列表优先显示活动/暂停任务，防止长任务被近期快速任务挤出界面。
- 容量上限沿用本地索引 20 万封限制；超过容量以任务错误提示，不静默截断或报告成功。正文与附件仍按需缓存。

验证包含平台账户校验/会话撤销/并发登录/写入失败、最近邮件按服务器内部接收日期筛选、十五年前邮件导入、稀疏 UID、取消继续、游标持久化、拒绝提交时游标不前进、UIDVALIDITY 变化、远端标记/删除/目录变化、调度去重/关闭/认证退避。前端 13 项测试、类型/格式检查、Go 全量竞态测试及 vet 通过；浏览器使用模拟 API 验证桌面/手机/局域网 HTTP，不修改真实账号或发送真实邮件。
