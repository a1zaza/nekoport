# 开发、测试、构建与维护

## 工具链与依赖

当前本机使用 Go 1.26.5、Node.js 24.18.0、npm 12.2.2。Go module 为 `github.com/a1zaza/nekoport`，声明 Go 1.26；Docker 使用 Node 24 与 Go 1.26。依赖由 `go.sum` 和 `web/package-lock.json` 锁定；无数据库、CGO 或系统邮件客户端依赖。

在 `web/` 执行 `npm ci --ignore-scripts` 安装前端依赖。协议库使用 go-imap v1 和 go-message；凭据为 AES-GCM，应用密码为 bcrypt 摘要。所有用户邮箱信息均由配置输入。

## 验证命令

项目根目录：

```bash
go test -race ./...
go vet ./...
```

前端 `web/`：

```bash
npm run typecheck
npm test
npm run format:check
```

Go 协议集成测试在随机回环端口运行临时 TLS IMAP 模拟服务器，使用临时 CA 和数据目录；需要测试进程有本机监听权限。SMTP 事务边界使用内存连接测试，覆盖最终响应丢失、部分收件人拒绝和日志提交失败。测试不使用真实邮箱或相邻项目数据。

`web/scripts/browser-check.mjs` 使用 `playwright-core` 和现有 Chromium，临时提供编译后的静态文件并模拟 API，验证桌面/手机布局、HTML 隔离、图片授权、草稿和发送。先生成前端产物，再在 `web/` 执行 `NEKOPORT_CHROMIUM=<浏览器绝对路径> npm run test:browser`。默认通过 `chromium.executablePath()` 获取 Playwright 配置的浏览器路径，缺少对应版本时从同一缓存目录选择已有 Chromium，也支持 `PLAYWRIGHT_BROWSERS_PATH`；不自动下载或安装浏览器。脚本结束关闭浏览器与服务器，截图保存到 `/tmp/nekoport-*.png`。这是 UI 集成验证，不是真实邮箱验收。

## 源码构建

先在 `web/` 执行 `npm run build`，再在根目录执行：

```bash
CGO_ENABLED=0 GOOS=linux go build -buildvcs=false -trimpath -o bin/nekoport ./cmd/nekoport
```

`web/embed.go` 内嵌构建阶段的 `dist`；服务入口检查 index.html，缺失时拒绝发布运行。源码中的 `.keep` 仅保证未构建时能够执行 Go 测试，不代表前端产物齐全。运行时无需挂载 dist 或启动 Node。

只有用户明确要求时才启动开发环境。开发启动时可直接运行后端，首次自动初始化主密钥与访问账号，并在控制台输出随机初始密码。后端 `serve -data .data -listen 127.0.0.1:8080 -master-key-file .data/master.key -origin http://127.0.0.1:5173,http://localhost:5173`；前端在 `web/` 执行 `npm run dev`。生产不要将开发 origin 带入配置。

前端开发脚本监听 `0.0.0.0:5173`，允许局域网访问；后端仍可保持 `127.0.0.1:8080` 并通过 Vite 代理提供 API。局域网访问时将实际前端地址追加到后端 `-origin` 参数，例如 `http://172.20.4.2:5173`。该 IP 是本机当前地址，网络变化后需重新核对，不使用通配来源白名单。

## CLI

- `keygen -master-key-file <路径>`：生成 base64 格式的 32 字节主密钥，权限 0600，拒绝覆盖。
- `init -data <目录> -username <名称>`：主密钥默认 `<目录>/master.key`，缺失且无已存凭据时自动生成；隐藏输入两次应用密码；可选 `-password-stdin` 从标准输入读取，不在命令参数中传密码。只允许第一次初始化。
- `serve -data <目录> -listen <地址> [-master-key-file <路径>]`：检查资源、锁目录、恢复必要索引，沿用或安全初始化主密钥，然后开放服务；不指定密钥路径时使用数据目录下 master.key。
- `healthcheck -listen <地址>`：访问本机就绪端点，不涉及邮箱认证。
- `version`：显示程序版本。

全新目录首次 serve 自动创建 admin 与 32 字符安全随机密码，仅在该次控制台输出；用户名和 bcrypt 哈希持久化，不生成明文账号密码文件。可选在首次启动前手动 init 自设账号。已有账号保持不变，不重复输出密码，不预置邮箱。当前没有远程注册或自动重置入口；登录后可在账户安全中验证当前密码并修改用户名/密码。忘记密码时的账户恢复应保留原目录，由后续专门维护工具处理，不手改历史日志。

## 镜像与发布

Compose 默认镜像为 `ghcr.io/a1zaza/nekoport:latest`；仓库地址已确定不代表镜像已发布。首次发布前可以显式使用 `NEKOPORT_IMAGE=nekoport:local` 执行本地构建与运行，见 README；默认主密钥随数据目录持久化，不再需要单独运行容器生成密钥。

`deploy/Dockerfile` 三阶段编译，`deploy/entrypoint.sh` 在无参数时提供 serve 默认参数；显式参数原样传递。默认容器地址 `0.0.0.0:8080`，Compose 映射宿主回环。自定义监听端口时同步调整 ports 与健康检查，不能只修改其中一处。

可使用 `sh -n deploy/entrypoint.sh`、`docker compose --env-file /dev/null config --quiet` 静态检查，不需要启动容器。镜像构建和运行必须有明确授权，不能由文档检查推断为已经验收。

GitHub Workflow 沿用 v2way 的双原生 runner、固定 Action commit、按 digest 推送后合并 latest。当前仓库为 `a1zaza/nekoport`，发布目标为 `ghcr.io/a1zaza/nekoport:latest`；工作流仍根据实际仓库路径动态生成镜像名，源码 OCI 标签指向 `https://github.com/a1zaza/nekoport`。构建缓存按架构隔离；只有两架构都成功才合并。流水线不部署运行中的服务。GHCR 包可见性自行决定，私有包需在部署端配置读取权限，秘密不写入 Compose。

## 数据布局与恢复

- `store.json`：格式版本与存储身份。
- `journal/*.jsonl`：连续序号、事务操作与 SHA-256 校验，单行最大 8 MiB；落盘同步完成后才返回成功。
- `checkpoints/g-*`：设置/队列状态 JSON 与每片 1000 条的邮件 JSONL；manifest 和最终提交记录校验完整性。
- `objects/<前缀>/<随机 ID>`：不可变正文、MIME 或附件原始字节；同名 `.json` 保存大小与校验和，读取时核验。
- `secrets.json`：认证加密后的凭据条目，密钥独立提供。
- `recovery/*.tail`：最后一个活动日志的不完整尾记录原件。

更新采用单写入锁；启动加载邮件定位、排序、未读统计、发送幂等关系等必要索引，不加载全部正文和附件。flags 更新不全量重排。缓存正文从对象文件读取，最大两个并发读取/解析任务；最多两个账号后台工作，最多配置 20 个邮箱，本地元数据上限 20 万封；超限停止新元数据写入并显示错误，不静默丢弃草稿或旧邮件。

每 1000 个事务或活动日志达到 16 MiB 时生成检查点；后台每 10 分钟补充检查点和保守对象回收。当前检查点在写锁内同步生成，确保视图一致；不是方案中的异步快照版本。保留两个检查点及较早一代恢复所需的日志。回收同时保护当前状态、保留检查点和日志引用，对象至少经过一小时宽限后才可能删除；不完整/失败操作的对象不会按容量强制清理。

正文搜索当前使用有界分批扫描，四秒预算返回 `partial` 与继续游标；元数据为内存筛选。不依赖二进制搜索索引；分片倒排属于后续性能增强。

停止时由 tini 转发信号，HTTP 请求与协议连接可取消，已提交事务不依赖退出保存。损坏或文件写入失败不能简单重试网络副作用：保留目录，先复制到备份位置，再定位错误；不使用空文件替换坏日志。恢复时尝试完整上一代检查点并验证后续日志能到达已知提交上界；无法恢复完整状态时拒绝启动。

离线备份要求服务已停止，复制整个数据目录（包含 master.key），完整备份限制为个人访问。密钥轮换、在线备份、格式升级转换工具和应用密码恢复工具暂不提供；应用拒绝不兼容格式写入。

## 页面外框

登录后的应用参照 v2way：桌面与平板四周保留 20px，外框使用 1px `#353535` 边框、10px 圆角和 `0 12px 45px #0002` 阴影，高度为 `100dvh - 40px`。宽度不超过 720px 时取消外框并铺满视口。登录页保持独立全屏布局。平板和手机侧栏、遮罩相对应用外框定位，弹窗与顶层下拉仍按视口定位。

## 字体与连接诊断

字体资源与 v2way 原文件保持一致，位于 `web/src/assets/fonts/`，通过 CSS 相对资源路径加载；Vite 发布构建会将字体和 `web/public/licenses/` 的授权说明纳入前端产物，再由 Go 内嵌。中文文件实际是霞鹜臻楷，CSS 的 `LXGW WenKai` 是为对齐参考项目保留的别名，不应改成只依赖系统字体。

连接错误分别标注 TCP 连接、TLS 握手、协议握手、STARTTLS 升级、认证方式与认证阶段。服务端回复经过用户名、密码及常见编码形式脱敏后显示；服务器认证拒绝只说明当前用户名/密码或账号策略未通过，不能单凭该错误认定密码错。网络中断、超时及 SMTP 临时 4xx 错误保留独立分类。没有自动尝试其他用户名或修改用户邮箱密码。

## 阅读区显示

纯文本正文用 pre 元素与文本节点显示，保留原始换行、空格和制表符；显式覆盖浏览器默认边距/字体，长 URL 和长行按容器宽度折行。HTML 邮件仍使用独立 sandbox iframe，生成文档时读取平台实际背景、前景、链接和边框色，移除旧式 bgcolor/color 等属性，避免白色页面或黑字在暗色主题下不可读。

在 `web/` 执行 `NEKOPORT_UI_SOURCE=1 node scripts/browser-check.mjs` 可直接验证源码，使用临时回环测试服务器，无需构建或启动开发环境；测试结束自动关闭。浏览器检查也可设置 `NEKOPORT_UI_URL=http://127.0.0.1:5173`，复用已运行开发前端并模拟全部业务 API；覆盖纯文本缩进、长行窄屏折行、主题配色与阅读隔离，不连接真实邮箱。

### 邮件样式保留（2026-11-24）

HTML 保留经过属性白名单筛选的内联样式、样式表、类名和媒体查询。平台背景仅强制应用在 html/body，内部卡片、表格和文本保留原配色。拒绝 CSS URL、导入、外部字体、转义和危险属性，即使允许远程图片也不开放 CSS 资源。旧版缓存通过 htmlVersion 检测，读取时从本地原始 MIME 恢复并持久化，无需重新同步；本节替代此前清理所有 style/bgcolor/color 的规则。

### 原始邮件配色与宽度（2026-11-24）

按用户要求取消邮件主题覆盖，不再给 HTML 正文设置平台背景、前景、链接或边框颜色。保留净化后的 html/body 背景与配色；未指定配色时使用浏览器浅色默认。600px 最大宽度应用在外部 iframe/纯文本容器，居中容器而非居中文本；小屏宽度 100%。HTMLVersion=3 从原始 MIME 恢复旧缓存的根属性及新增允许的排版样式。本节替代此前“根背景跟随平台”的规则，安全过滤与图片授权策略保持有效。

### 正文自适应高度（2026-11-24）

MailFrame 组件自动测量文档，使用 ResizeObserver 和资源 load 事件覆盖正文加载、图片尺寸变化及手机宽度变化，邮件 iframe 不显示内部纵向滚动条，长邮件由外层阅读区统一滚动。最大宽度更新为 600px。sandbox 允许同源只为宿主读取布局，保持脚本禁用，并显式设置正文 CSP script-src none；绝不能同时添加 allow-scripts。切换邮件/HTML/纯文本和卸载时清理观察器。浏览器回归覆盖长正文、动态高度和桌面/手机无内部纵向溢出。

### 局域网写信白屏排查

如果 localhost 正常而局域网 HTTP 点击写邮件/回复白屏，先检查控制台是否报 crypto.randomUUID is not a function。该方法依赖安全上下文，Compose 改为使用 getRandomValues 生成发送幂等键，惰性初始化且失败重试时保持不变。回归测试显式模拟 randomUUID 不存在并验证重试键一致；浏览器脚本同时覆盖新建与回复，应使用局域网来源再运行一次，避免 localhost 掩盖限制。

## 账户安全与同步任务

设置页的“账户安全”可只修改用户名，或打开“修改密码”填写新密码与确认。始终验证当前密码，成功后所有会话（包括其他标签页与 SSE）失效；先保存并关闭写信窗口。验证失败保留编辑；存储错误不确认更新。新密码按 bcrypt 约束至多 72 UTF-8 字节。没有找回旧密码或显示密码的接口。

点击每个邮箱卡片上与“编辑连接”同级的“同步设置”，在弹窗中选择最近 N 天/全部历史、开启定时对齐并设置 1–1440 分钟间隔。“同步全部历史”立即创建读取任务并将范围设为全部；“立即对齐”按当前范围完整核对。查看任务可展开各目录进度，取消保留已导入内容，继续/重试从已提交进度恢复；已完成目录在部分重试时保留。账号暂停时先恢复账号，移除账号前取消任务并等待工作结束。

增量同步改为 IMAP IDLE 事件驱动，不再使用快速同步周期；旧检查点中的 quickSyncIntervalSeconds/nextQuickAt 不参与调度，旧页面提交的快速间隔字段兼容接收但忽略。完整对齐仍默认每 15 分钟，可按邮箱调整或关闭。启动时发现目录，重新建立监听只做当前目录的增量补偿；服务停止期间不运行任务，不补跑每个错过的周期。读取任务可恢复，SMTP/归档结果不确定仍不得自动重放。

结构化任务随检查点/JSONL 恢复；一轮 UID 上界和已提交游标持久化，不存整个 UID 列表。窗口跨度至多 10000，FETCH 至多 100 封，执行片至多 8 步后释放工作槽；同账号串行、全局两个后台槽。首次完整任务仅补录元数据，后续手动/定时完整任务还下载全部正文及 MIME 附件，规则见下文“完整任务下载正文及附件”；不等同独立备份，上限 20 万封，超限明确报错。

测试使用本地 TLS IMAP 和模拟 API；可执行 `go test -race ./...`、`go vet ./...`、前端测试与局域网浏览器脚本。容量测量可用 `go test ./internal/storage -run '^$' -bench BenchmarkHistoricalIndex -benchtime=10x -count=1`，结果不可当作真实服务商网络同步性能保证。方案和数据见 account-history-sync-plan.md。

### 邮箱共用登录信息

添加/编辑邮箱仅填写一组用户名和密码，接收/发送共用；IMAP 与 SMTP 仍分别配置主机、端口和 TLS。编辑时密码留空沿用已保存的接收密码，并在保存时用于 SMTP。界面始终提交 useSameCredentials:true，复用现有服务端空密码处理，保留旧数据格式；打开弹窗不会读取或改写真实密码。

### 纯文本阅读宽度

纯文本 pre 铺满阅读区，不设最大宽度和水平居中；保持原换行、缩进、内边距及长行折行。HTML iframe 铺满阅读区，遵循邮件本身宽度，外层布局容器水平居中。此规则替代之前对纯文本也使用 600px 的描述。

### 邮件地址展示（2026-11-25）

原始 From/To/CC/Reply-To 保留邮件头格式，用于回复与地址解析；接口额外返回可读显示字段，Go 端解析语法引号并解码 UTF-8 Base64/Q、GBK 等 MIME 名称。列表使用 fromName，详情使用 fromDisplay/toDisplay/ccDisplay，发件箱使用可读地址；头像取显示名首个 Unicode 字符。名称内部有意义的引号保留，损坏或不支持的编码回退原文，不将地址插入 HTML。派生字段不回写持久化状态，已有邮件无需迁移或重新同步。

### 临时请求失败与恢复提示（2026-11-25）

页面 bootstrap、邮件列表、同步任务读取的网络错误使用可恢复提示，原有数据保留。下次对应读取成功会自动清除自己的提示，也可手动重试/关闭；浏览器 online 事件触发页面刷新。发送、保存等写操作失败独立显示，不因其他后台请求成功而误清除，不自动重试写操作。

useBackgroundRefresh 串行读取并将突发刷新合并为一次后续请求；退出/卸载时中止并作废旧结果，避免旧失败在恢复后重新显示，也避免持续 SSE 打断慢请求。邮件列表取消时不报错，成功才清除列表提示；同步任务 5 秒轮询沿用该串行保护。Failed to fetch 等 fetch 错误在 api 层统一为中文 NetworkError，AbortError 不转换。没有增加全局固定周期轮询，也没有以固定超时隐藏真实错误。

## 待处理问题

以下问题来自 2026-11-25 的代码审查，当前尚未修复；后续修复须更新此清单并写入月度 changelog，不依据历史运行快照覆盖用户配置。

- **保存全部历史范围会提前对齐**：`UpdateSyncSettings` 在 `scope=all` 时无条件清零 `NextFull`，即使只更改周期等设置，也会立即触发完整对齐。
- **关闭定时对齐后的失败任务恢复**：`scheduleSync` 的失败任务恢复分支位于 `ReconcileOn` 检查之前，之前失败的 timer/reconcile 任务仍可能被自动恢复。
- **登录初始重复读取**：主动 bootstrap 与 SSE 初始 refresh 仍可能各读取一次；已有串行合并可避免并发，但不保证只请求一次。
- **隐藏页面的全局刷新**：SyncPanel 定时查询检查可见性，但全局 SSE 刷新尚未检查页面可见性。
- **分页被后台刷新重置**：bootstrap 成功递增 tick 后，邮件列表重新请求第一页并替换 items，已“加载更多”的内容会丢失；正文不随 tick 重复下载。

bootstrap/SyncPanel 读取重叠、旧响应覆盖与 Failed to fetch 提示残留已由 useBackgroundRefresh 等逻辑修复，不再作为未完成项。历史经过见 [2026-11 changelog](changelogs/2026-11.md)。

### 邮箱文件夹显示顺序

### IMAP IDLE 生命周期

当前规则（2026-11-26）：日常 IDLE 使用按目录/UID 的 delta，与手动、定时 reconcile/history 分离。局部任务不更新 LastFull/NextFull；旧任务缺少范围字段时沿用原有行为。细化设计与实施对照见[方案](idle-delta-sync-plan.md)。

- 协议读取线程直接解析不可变事件，不依赖异步可变 MailboxStatus。EXISTS/RECENT/UIDNEXT 只拉对应目录新 UID；FETCH 携带 UID 时仅读取该 UID 的 flags，缺 UID 则核对当前目录已有 UID；EXPUNGE 对当前目录进行存在性二次确认，并保留新增线索。UIDVALIDITY 变化只重建当前目录，旧代次操作失效。
- SELECT 的基线通知和重复 UIDNEXT/UIDVALIDITY 不作为新变化；PERMANENTFLAGS/READ-ONLY/READ-WRITE 只更新连接模式信息，不触发数据扫描，也不把 EXAMINE 只读模式当作账号无写权限。
- 每个监听目录使用只读 SELECT + IDLE；直接执行 IDLE，禁止库的 NOOP 回退。不支持时提示并保留手动/完整对齐。IDLE 确认与 DONE 各 10 秒超时，每 25 分钟正常续期，不创建补偿任务，依据 [RFC 2177](https://www.rfc-editor.org/rfc/rfc2177.html)。
- 断开仅进入退避，不立即扫描。重连成功合并一次当前目录的新增、已有 UID flags 与存在性核对。退避为 1、2、4…256 秒加至多 25% 抖动，稳定一分钟后复位。明确认证拒绝停止自动连接重试；连接配额/临时不可用不冒充密码错误。
- 每账号 IMAP 连接预算默认 10，可在编辑连接中设为 4–50；IDLE 最多总数减 3，其余连接留给发送归档、同步、正文与连接检查。额度不足时保守减少监听，优先最近查看目录、收件箱、已发送和归档；bootstrap 显示可选择目录总数与未监听名称。查看目录只调整内存监听偏好，不写邮件数据；没有循环轮换或后台 SELECT 轮询。
- 事件按账号/目录合并约 500ms，持续风暴最多等待 2 秒取一批；UID 集合超过 1000 降级为当前目录核对。入队的 delta 持久化执行范围、原因集合、进度与重试截止时间；每目录只有一个待领取批次，运行后到来的事件进入后续批次。启动目录恢复覆盖尚未持久化的内存事件窗口。
- 单个目录失败独立退避，不冻结其他目录；发现已删除目录时结束该目录残余读取任务。增量与完整任务按执行片轮流让出同账号机会，沿用全局两个后台槽、每片最多 8 步、FETCH 每批 100 封。启动重建 UID 排序内存索引，避免每批重新复制排序全部元数据。
- 新基线有版本标记，初始补录失败后仍按原范围恢复，不把“已经 SELECT 过”当作初始补录完成。建立基线后新 UID 不按旧 INTERNALDATE 排除，移动旧邮件同样导入；最近 N 天仍用于初始/历史补录。
- 目录发现只执行 LIST，不等同全账号邮件扫描。新建/改名未被通知时仍由手动或定时完整对齐发现；SELECT 目录不可用时进行一次目录发现，NoSelect 保留身份。关闭、暂停、账号修订或冻结存储取消对应监听，旧修订内存需求作废。

协议回归统计实际 LIST/SELECT/SEARCH/FETCH 的目录与参数，验证单 UID、删除和目录重建没有越界扫描；集成回归覆盖双目录离线移动、改名删除、本地 MOVE 无事件补偿、旧日期新 UID、事件突发和检查点恢复。所有测试仅使用本地 TLS 模拟与临时数据。

### 远端删除与移动的同步时机

普通同步按钮和 IDLE 的 EXISTS/RECENT 通知调用 quick，检查水位之后的新增 UID；EXPUNGE、FETCH 标记变化及 UIDVALIDITY 等状态变化则排队当前目录/UID 的 delta。服务器归档或移动表现为目标目录新增 UID、源目录 UID 消失：补偿分别覆盖受影响目录，按账号/目录/UIDVALIDITY/UID 核对，不以 Message-ID 跨目录去重，不直接用 EXPUNGE 序号删除本地邮件。本地 UID MOVE 前记录目标 UID 下界，成功后原子保留来源与目标的目录补偿，目标未初始化时也不丢失此次移动的旧日期副本，即使服务器未推送事件也能收敛。目录扫描不是跨目录事务，任务执行中允许短暂过渡状态，后续事件和补偿任务负责最终一致。

“同步设置 → 立即对齐”调用 reconcile；history 也执行完整对账。每个目录完整扫描成功后，对本轮未见记录逐批精确 SEARCH 二次确认，只删除确认缺失的本地记录和索引，不执行远程 EXPUNGE；已有旧邮件也参与核对，不因“最近 N 天”的补录范围而被忽略。全部目录无失败后，再次完整 LIST，清理确认消失目录内的记录，最后移除空的本地目录。NoSelect 仍视为存在。目录 SELECT 失败、搜索/抓取失败、取消或配置变化不授权按该失败推断删除；任一目录失败会跳过本轮消失目录的整体清理。

完整对齐默认 15 分钟，但用户可设为 1–1440 分钟，不能以文档默认值解释实际运行状态。普通“同步”不会强制触发完整对齐；需要立即反映远端删除时使用“立即对齐”。记录身份是账号/目录/UIDVALIDITY/UID，不以 Message-ID 跨目录猜测去重。

### 同步日志分类与保留（2026-11-25，当前规则）

同步设置的“同步日志”保持默认折叠，按“完整对齐”和“增量同步”两个页签展示。全历史同步属于完整对齐，quick/delta 属于增量；任务显示整个账号、目录或 UID 范围及具体原因。每邮箱每类分别保留最近 5 次已结束任务（按最后更新时间排序），进行中和暂停任务额外保留以便恢复；创建、终结任务和启动恢复时清理过期记录，快速任务不挤掉完整对齐记录。此规则替代此前保留 20 次混合终态摘要的实现。

任务和目录显示核对、新增、更新、未变、删除、未补录统计，展开后显示创建/开始/结束时间、触发来源、补录范围、目录快照的本地与服务器总数、批次 UID 范围和执行原因。核对计数是成功提交的记录比较次数，包括删除二次确认和重试中的再次比较；更新排除仅 revision/同步代次的变化；未补录包含读取后因补录范围被排除的邮件。目录快照不是跨目录原子快照，服务器总数可能大于限定范围的导入数量。快速同步未检查的旧 UID 不计作已核对。

详情记录发现新目录、目录快照、比较批次、缺失 UID 二次确认、UIDVALIDITY 变化、消失目录本地清理、完成、失败、取消、继续和设置导致暂停。日志基于真实索引写操作生成，与邮件索引在同一笔 JSONL 事务提交，失败不单独推进计数；日志不保存正文、凭据或协议认证对话。每任务保存最近 200 条过程明细，较早明细省略时显示数量，任务和目录累计计数完整保留，避免大邮箱使单笔日志超过存储限制。

新增 group=quick/full 可筛选 GET /api/v1/accounts/{id}/sync-tasks，原列表分页保持兼容，任务详情接口继续返回完整保留明细；bootstrap 不包含过程明细，避免 SSE 刷新重复发送大日志。设置弹窗每 5 秒在页面可见时分别刷新两类任务，关闭时取消。

旧任务仍可显示既有状态与进度，明确提示“旧版任务未记录新增、删除明细”；新任务开始记录，不根据当前邮件反推历史变化。继续任务的计数累计已提交结果，配置变化导致重新枚举时保留日志并记录原因。

### HTML 邮件自身宽度（2026-11-25，当前规则）

HTML iframe 铺满阅读区，取消平台的 600px 最大宽度限制。保留邮件 html/body 及原有外层 div/table/main/article/section/header/footer 的 width、max-width、display 与文字对齐；仅把这些外层容器的水平边距设为 auto，使其在可用空间中居中。内部元素的边距与排版不覆盖，不额外包装正文，保持原 CSS 选择器结构。没有声明宽度的邮件按浏览器正常块布局使用可用宽度，窄屏遵循邮件自己的响应式规则。

继续通过 MailFrame 自动撑高，长邮件由外层阅读区滚动；纯文本维持全宽 pre，不居中。此规则替代此前所有平台固定 600px 的约定，只涉及前端展示，不变更净化白名单、HTML 缓存版本或服务器邮件内容。

### Actions 缺失 internal/secrets 的原因与修复

Git 的 `secrets/` 规则会忽略任意层级同名目录，曾导致 `internal/secrets/vault.go` 和 `vault_test.go` 没有进入首次提交。它们是加密凭据的程序源码，不是实际凭据文件；缺失时 Go 对本模块内部路径报“no required module provides package”，不能通过 go get 修复。实际部署密钥位于根目录 secrets，忽略规则限定为 `/secrets/`，同时继续忽略 .data。

本地测试和 Docker 构建读取工作目录，仍可能使用未提交甚至被 Git 忽略的源码，所以本地通过不代表远端检出完整。修复规则后，两份源码都必须纳入提交；仅提交 .gitignore 不够。发布工作流在检出后使用 git ls-files --error-unmatch 检查这两个文件，缺失时在镜像构建前失败。

此次验证从 Git 跟踪文件及未被忽略的待提交文件导出干净目录，排除本地数据、密钥、node_modules 和旧 dist，在其中完成 Go 全量竞态测试、vet 与 Docker 构建，镜像为 nekoport:ci-check（linux/amd64）。这验证了待提交修复，不代表当前远端 HEAD 已修复；提交后还应以实际检出/归档快照为准。

### 单数据目录与主密钥自动初始化（当前规则）

Compose 仅挂载 ./data 到 /var/lib/nekoport，默认主密钥为 /var/lib/nekoport/master.key。CLI init/serve 不指定 -master-key-file 时使用 -data 目录下的 master.key，显式参数仍可沿用外部只读密钥。全新数据目录首次 serve 自动生成默认访问账号，手动 init 仍可选；首次启动或 init 自动准备密钥，已有账号启动时也执行同样的密钥检查。

新密钥权限 0600，使用临时文件写入并同步后以不覆盖的原子硬链接发布，再同步目录；并发初始化复用同一完整密钥，不留下半写入目标。已有密钥只校验、读取，不替换或改权限。文件为空/无效、凭据文件损坏/存在加密条目，或账号保留凭据引用却缺少密钥时明确报错，不生成替换密钥。

旧版本独立挂载的 secrets/master.key 必须在服务停止后原样迁至 data/master.key，不能重新生成；迁移方式见 README。当前完整备份包含 master.key，需保护整个数据目录和备份；此规则替代此前密钥独立挂载、显式生成的默认部署约定。

### 首次启动账号仅输出控制台（当前规则）

全新数据目录首次 serve 在资源、主密钥和监听端口可用后创建 admin，密码来自 24 字节 crypto/rand 熵、编码为 32 字符。账号持久化只含用户名、bcrypt 哈希和修订；提交成功后一次性写入标准输出，不创建 dev-account.json 或其他明文凭据文件，不在 API 返回密码。Docker 用户通过 docker compose logs nekoport 查看首次日志，登录后可自行改密。

已有完整账号不变更、不重新输出；人工 init 的自定义账号也保留。账号字段不完整、密码哈希无效，或已有业务数据/访问修订但缺少账号时拒绝自动创建，避免把损坏或丢失配置当成新安装。先绑定端口再提交初始账号，端口占用不消耗首次密码；写入失败不输出，控制台输出失败会报错且不自动重置已提交账号。崩溃或日志丢失不能从密码哈希恢复明文。已有旧明文凭据文件不由程序使用、更新或据此重置账号，实际账号以持久化配置为准。

### 访问主机与请求来源

服务不再对 HTTP Host 执行 localhost/Origin 白名单检查，自定义域名、局域网 IPv4 和 IPv6 地址可用于读取页面、会话与就绪检查，不再返回“请求主机不受信任”。受保护 API 仍要求登录会话；写请求仍校验 Origin 和 CSRF，额外允许的来源仍使用 -origin 精确配置，不接受通配。

反向代理应保留浏览器访问的 Host，使 Origin 与应用看到的 Host 一致；若代理改写 Host，必须保留现有明确的额外 Origin 配置。此次调整不信任 X-Forwarded-Host/Forwarded 等客户端可伪造的转发头，也不更改监听地址、Compose 端口映射或 CORS 策略。

### 发送后的已发送目录更新（2026-11-26）

SMTP 接受、已发送副本保存、本地索引刷新分别处理。默认 APPEND 到 sent 后，任务结果与该目录新增读取任务同事务保存；未发现 sent 时先 LIST 发现，不创建未知远端目录。即使没有 IDLE 通知，本地也会刷新。autoArchive=true 不重复 APPEND，界面显示“由服务器保存，尚未核实”；若服务端异步保存且没有通知，后续手动/完整对齐仍负责发现。

SMTP/APPEND unknown 不自动重放；APPEND 成功或结果不确定后的核对仅执行读取。已有“重试归档”只处理明确失败，不重发 SMTP；归档 unknown 的完整人工处理闭环仍是后续工作。集成测试使用本地 TLS SMTP→IMAP APPEND→sent delta，覆盖无 IDLE 通知、服务器保存模式、SMTP 最终确认丢失、APPEND 写入后返回错误；均检查只发送/追加一次。


### 完整任务下载正文及附件

当前规则（2026-11-26）：账号首次成功的完整任务仍仅按配置补录邮件列表，不批量下载正文；此前失败/取消的首次任务恢复后仍沿用首次策略。之后手动或定时触发的 reconcile/history 覆盖所有可选择目录的全部邮件，不再受首次“最近若干天”范围限制，但不改写账号保存的范围偏好。先完成元数据扫描、删除核对，再逐封保存原始 MIME、解析正文与全部 MIME 附件（含内嵌附件）。IDLE/delta/quick 只更新元数据，不启动批量下载。旧账号已有非零 LastFull 即视为完成首次；任务创建时保存策略，旧未完成任务执行时补齐策略。

使用 UID FETCH BODY.PEEK[]，不改变已读状态；每轮仅下载元数据快照 UID 上界以内、仍存在于本地索引的邮件，期间新增邮件由增量与下一轮完整任务补齐。已有原始 MIME、正文及附件对象齐全时直接复用，缺失时重取该封完整 MIME。完整任务保存或复用的内容标记为保留，不参与普通 CacheMiB 预算的淘汰；后续阅读仍按需读文件，不将全部正文加载进启动内存。远程 HTTP 图片不属于 MIME 附件，不随此功能下载。

单封原始 MIME 上限 30 MiB、单个解码分片上限 20 MiB、最多 200 个分片及正文对象 32 MiB 限制继续有效。超限、缺失 UID、解析失败或 UIDVALIDITY 变化记录具体失败并继续处理其他邮件，任务最终为 partial_failed；传输或磁盘写入错误停止当前批次，不推进该封游标。只有完整成功才更新 LastFull/NextFull；不会用元数据阶段结束冒充下载成功。

对象引用、目录下载游标与统计在同一事务提交，重启恢复已有进度；手动重试会重新扫描本次下载阶段并复用已有文件，避免重复网络下载，必要时先重新对齐失败目录。任务/目录展示已下载、已复用、失败数和本次保存字节数。正文下载统计按本次尝试计数（手动重试清零），元数据比较统计沿用累计语义；两类统计不混计。原有每邮箱每类最近 5 次终态、每任务最多 200 条详细日志规则继续适用。

保留内容没有总量硬预算，需为全部邮件预留磁盘空间；存储写入失败仍按既有规则进入故障保护。服务器删除/移动或删除账号后索引仍会清理，孤立对象由既有延迟 GC 回收，因此不是独立备份。新增 Go 逻辑需更新服务后生效，本地不会自动启动真实下载或更改邮箱配置。


### 邮件操作本地优先

当前规则（2026-11-26）：POST /message-operations 只验证并在本地 JSONL 事务保存操作意图，返回 202 后立即更新界面，不等待 IMAP 或后续 bootstrap。移动、删除和归档共用该流程；删除仍是安全移动至同账号已删除目录，不永久删除。入队失败保留原列表、选择和邮件状态。

queued/running 的移动操作构成持久化展示投影：邮件从列表、搜索、未读计数及概览总数中暂时移出。真实 messages 记录、原始目录、UIDVALIDITY/UID 和正文附件引用仍保留，供后台提交和失败恢复；不伪造目标 UID，也不把源 UID 当作目标 UID。目标目录在安全 UID MOVE 和两端 delta 核实后显示真实记录，因此后台确认前目标目录可能暂未出现邮件。刷新或重启不会丢失已排队的投影；旧版待执行移动同样生效。

服务器拒绝、连接失败或执行中断后，移动解除投影，仍存在的来源记录恢复可见并保留失败日志；移动可能已在远端完成时仍按原有两端读取补偿核对，不自动重发 MOVE。成功保留原有来源删除与两端 delta 同事务的流程。重复移动、同目录移动、跨账号移动及 NoSelect 目标拒绝入队，重复提交的邮件 ID 在事务前去重。

已读/星标在入队时更新本地标记，并保存原值；未开始的同类标记合并为最新意图，后台领取时重新读取任务，避免发送旧快照。执行中同类标记不叠加；已有标记任务不阻止随后排队移动。失败或重启中断时回滚对应标记，不覆盖更新的操作。显式重试标记时重新记录当前原值并同步恢复待提交状态，移动仍必须同步核对后重新选择。

前端在受理时直接更新列表、正文标记、选择和来源计数，删除确认不等 bootstrap 才关闭。进行中的旧列表/分页响应以操作版本判定过期，不能把已移出邮件或旧标记重新覆盖；后台刷新用于确认或恢复状态。新增后台操作失败提示，可进入设置查看记录。任务仍由原有账号工作队列执行，网页不负责向 IMAP 提交。模拟浏览器回归增加“bootstrap 阻塞时移动仍立即反馈”的断言。


### 失败操作记录处理

设置页“未完成的邮件操作”支持单条“清除记录”和“清除全部失败记录”；仅移除 failed 记录，不删除邮件、不撤销或重放远端操作。等待/执行中的任务不能清除，批量清理也会保留这些任务。清除后由正常刷新移除全局失败提示；失败请求保留记录并显示错误，操作请求期间禁用相关按钮。

已读/星标失败可重试；移动/删除失败提供“同步核对”，通过 POST /operations/{id}/reconcile 为仍存在的来源目录和目标目录创建 delta 读取任务，并保留此前保存的目标 UID 下界与 UIDVALIDITY。核对不重发 MOVE，不触发账号全量任务或正文批量下载，不直接把失败记录改成成功；等待核对完成并确认位置后可清除记录。邮箱暂停/不存在或来源和目标目录均不可用时明确拒绝，后者应使用邮箱完整对齐。

DELETE /operations/{id} 幂等清除单条失败记录；DELETE /operations 清除全部失败记录。两者在存储事务中校验状态，任何非 failed 单条记录拒绝清除，避免与后台领取任务竞态。接口沿用会话、Origin 和 CSRF 校验；记录清理没有 IMAP 副作用。
