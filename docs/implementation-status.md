## 采用的保守取舍

这些取舍已写入代码和维护说明，避免把架构演进目标误认为当前能力：

- 增量使用 IDLE，连接限制和目录未通知的变化仍需完整对齐；不支持 IDLE 不回退轮询。CONDSTORE/QRESYNC 尚未实现；认证拒绝停止自动连接重试，修改连接配置后恢复。
- 首次范围通过账号同步天数配置；不提供专门的“继续加载更早服务器邮件”按钮。列表“加载更多”仅分页本地已同步元数据。
- 移动要求服务端支持 MOVE；缺少已删除文件夹时返回说明，不永久删除，不执行可能误删其他客户端标记邮件的 EXPUNGE。
- 检查点在写锁内同步生成，确保状态一致。每 1000 次事务或 16 MiB 日志触发；后台每 10 分钟补充维护，保留两代恢复链。未来可按性能证据改为后台不可变视图。
- 当前正文搜索为有时间预算的扫描；派生分片倒排、远端搜索和附件内容搜索属于后续增强。
- 当前没有正文对象的常驻 LRU；使用按需读取、大小校验和两个并发正文任务控制资源。必要索引常驻，最多 20 个邮箱、20 万封元数据；不声称满足任意邮件规模或严格 RSS 上限。
- 缓存配额针对当前引用的可重取正文/附件。保留日志、检查点和一小时回收宽限会有额外磁盘占用，磁盘预算不是整个数据目录的硬上限。
- 草稿仅在应用侧保存，浏览器必须能连接 Go 服务；无服务器草稿互通或 PWA 完全离线支持。
- 无 OAuth、富文本编辑器、桌面端、多用户、远程托管、规则引擎、联系人管理、会话聚合或自动更新。
- 无在线备份、密钥轮换、密码恢复或数据格式转换工具。当前格式版本不兼容时拒绝写入；完整恢复使用停机备份和对应程序版本。
